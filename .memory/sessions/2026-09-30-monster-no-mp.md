# 2026-09-30 몬스터 MP 칸 제거 (브랜치 claude/gifted-ramanujan-y6xska, #12 병합 뒤 main에서 다시 만듦)

사용자 요청: "몬스터는 MP를 사용하지 않는 걸로 변경했어, MP를 빼줘". 범위를 물었고(화면만 / 화면+데이터 /
완전 제거) 사용자가 **몬스터에게서 MP 칸 자체를 삭제**를 골랐다. 계획을 보여 주고 승인받음.

## 조사 (바꾸기 전)
- 데이터: 28종 모두 `"최대MP"` - 10종 0, 18종 "미정". 적 참가자는 `현재MP` = 0으로 시작했다.
- 적 참가자를 만드는 곳은 `combat/participants._적_참가자_생성` 하나. 몬스터 행동/반응/효과 코드는 `현재MP`를
  읽지 않는다(grep). MP를 확인/소비하는 곳은 `skill_system.사용_가능여부`/`자원_소비_처리`뿐이고 아군만 온다.
- 화면: 적 이름표 "HP n  MP 0".

## 바꾼 것
- `_적_참가자_생성`: `현재MP` 칸을 만들지 않고 `최대MP`도 읽지 않는다.
- 데이터 28종의 `"최대MP"` 줄 삭제(몬스터 데이터에 "MP" 문자열이 하나도 남지 않음).
- `사용_가능여부`: MP소모가 0이면 MP를 보지 않고, 칸이 없으면 보유 0으로 본다(MP 드는 스킬은 거부).
  `자원_소비_처리`: MP소모가 0이면 MP 칸을 건드리지 않는다. 아군 동작은 그대로.
- 화면: 적 이름표는 "HP n"만.
- 테스트: `test_몬스터에는_MP_칸이_없다`(적 참가자/데이터에 MP 없음, MP 0 스킬은 가능하고 칸이 생기지 않음,
  MP 드는 스킬은 "보유 0"으로 거부).

## 골든
14개 파일에서 1516줄 삭제 - 적 진영 참가자의 `"MP"`와 몬스터 원본의 `"최대MP"`뿐. 이전 골든 JSON에서 그 키만
지운 것이 새 골든과 정확히 같음을 스크립트로 확인(아군 MP는 그대로).

## 진행 중 문제 / 틀렸던 가정
- 작업 중 셸 명령 승인 확인이 여러 번 응답하지 않아(도구 쪽 일시 오류) 편집 도구로 코드를 고치고 검사를 미뤘다.
- 조사 때 "현재MP를 읽는 곳"을 game/ 아래만 찾았다 - 테스트 도우미 `test_combat_skills.참가자_요약`도 모든 참가자의
  `현재MP`를 읽고 있었다(KeyError). MP 칸이 있을 때만 기록하게 고쳤다.
- 새 테스트가 스킬 자원을 먼저 소비해 뒤의 MP 검사가 "행동 없음"으로 걸렸다 - 순서를 바꿨다.
