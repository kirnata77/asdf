# 2026-09-30 전리품 지급 + 전투 종료 팝업 (브랜치 claude/gifted-ramanujan-y6xska, #6 병합 뒤 main에서 다시 만듦)

사용자 요청: 전투가 끝나면 "전투 승리! / 전리품 / 골드 10 / 장비 A / 장비 B" 팝업. 조사해 보니 **전리품 지급 자체가
없었다**(monster_format.py에 "아직 어디에도 구현돼 있지 않다"). 물어서 정한 것:
- "미정"인 획득골드/드랍표 -> 골드 0, 드랍 없음. (29종 중 골드 값 있는 것 3종, 드랍표 있는 것 4종 - 2026-09-30 실행으로 셈)
- 같은 아이템은 "이름 x2"로 묶는다. 없으면 "전리품" 다음 줄에 "없음".
- 패배는 "전투 패배!", 도망은 "도망쳤다!" 팝업(전리품 없음). 보스전 포함 모든 전투.

## 구현
- `game/system/loot_system.py`(새 모듈, file_path.py 등록): 골드 "a~b" 균등, 드랍표 가중형/독립형,
  "아이템조건"(카테고리 방어구 + 레어도/티어). 확률은 0.3 / "1/25" 모두 받는다.
- `gameflow._전리품_지급`(전투_결과_정리에서 승리 시) -> 소지품에 넣고 `게임상태["전투_전리품"]`,
  `gameflow.전투_종료_문구`가 팝업 줄을 만든다. 카탈로그에 없는 이름은 주지도 보여주지도 않는다.
- 화면: 전투가 끝나면 바로 정리 + 팝업, [확인]이 마을/던전으로 보낸다(예전의 "전투 종료: 결과" + 확인 버튼 대체).

## 골든
`scenario_campaign.json`만 바뀜 - 승리마다 전리품을 굴려 random 흐름이 달라져 **무작위 인카운트 기록만** 달라졌다.
인카운트 줄을 뺀 나머지(보스 결과, 레벨, 개방)는 이전과 같음을 스크립트로 비교했다.

## 틀렸던 가정
- 드랍표 주석은 커먼 1티어 방어구를 25종이라 하지만 카탈로그에는 40종이다(아이템조건 테스트를 개수 대신 조건으로 검사).
- ui_smoke에서 레벨 1 몬스터(힐가브, 타우 아미)는 거너의 전투시작 반응에 바로 쓰러져 팝업이 먼저 뜬다 -
  스모크는 레벨 6/차수 2로 열고, 이미 끝났으면 강제 종료를 건너뛴다. 팝업 제목("전투 종료")도 본문과 구분.
