## 결정

- **CRLF 저장 방식: `* -text`(git이 변환하지 않음, 저장소에 CRLF 바이트 그대로).**
  `text eol=crlf`(저장소 LF, 작업트리 CRLF)도 가능했지만, 사용자가 GitHub 웹 업로드/다운로드를
  쓰므로 "저장소 바이트 = 받은 파일"이 덜 헷갈리고 각자의 `core.autocrlf`와 무관하다. 대신
  새 LF 파일이 들어오는 것은 git이 막지 않으므로 테스트(`test_repo_hygiene`)와
  `tools/fix_eol.py`로 강제. `.githooks/`만 LF(sh).
- **줄끝 커밋을 둘로 나눔**: 순수 변환(`1644c57`, `--ignore-cr-at-eol` diff 비어 있음) ->
  `.git-blame-ignore-revs`에 등록, 규칙/도구/테스트는 다음 커밋.
- **테스트 방식 두 가지**: 규칙은 정확한 값(`test_systems_*`, `test_combat_rules`), 데이터가
  많은 곳은 전수 스윕 + 골든(스킬 62, 몬스터 패턴 73, 상태이상 20, 버프 21, 디버프 20). 스윕은
  데이터가 늘면 자동으로 따라온다.
- 진행도/보상 흐름을 볼 때는 `support.강제_승리`로 전투 결과만 확정(전투 규칙은 따로 검사).
