# 2026-09-29 (3) - 줄끝을 CRLF에서 LF로 되돌림

## 요청

"잘못 말했다. 저장소 전체를 CRLF가 아니라 LF로, 그리고 규칙으로." - 앞 세션
(`2026-09-29-scenario-tests.md`)의 "전부 CRLF" 결정을 사용자가 정정했다.

## 결정

- **`* text=auto eol=lf`** - CRLF 때의 `* -text`(git 변환 없음)와 달리 이번엔 git의 표준
  정규화를 쓴다. LF가 git/리눅스/CI의 기본이라, 커밋 때 CRLF를 LF로 바꿔 주는 정규화가
  "Windows 편집기가 CRLF로 저장"하는 흔한 실수를 스스로 막아 준다. 훅 예외도 필요 없어졌다.
- 정규화를 거치지 않는 GitHub 웹 업로드는 테스트(`test_모든_텍스트파일은_LF`)와
  `tools/fix_eol.py`로 잡는다.
- **변환과 규칙을 한 커밋에** - CRLF 때는 변환만 먼저 커밋했지만, 이번엔 CRLF를 요구하는
  테스트가 이미 있어서 변환만 커밋하면 게이트가 빨개진다(깨진 상태 커밋 금지). 그래서 한
  커밋에 넣고 blame 무시에 등록했다 - 그 커밋의 규칙 몇 줄도 blame에서 건너뛰는 비용은 감수.

## 헛발질

- 첫 변환 스크립트가 `git ls-files` 출력의 따옴표로 감싼 한글 경로를 못 열어 149개에서
  멈췄다 - `git ls-files -z`로 다시 돌려 나머지 47개를 변환.
