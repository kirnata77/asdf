# 세션 핸드오프

핸드오프는 git, PR, 저장소의 상태 기록이 이미 갖고 있지 않은 것을 쓰지 않는다. 결과물은 문서가 아니라 짧은 시작 프롬프트다.

## 1. 새 일을 멈춘다

지금 단계를 끝낸다. 새로 시작하지 않는다.

## 2. 작업을 끝내거나 보류한다

- **끝났으면:** 보통 흐름(`repo-workflow`): 게이트, 커밋, push, PR.
- **끝나지 않았으면:** 자기 브랜치에 커밋한다(`main-branch`에는 하지 않는다). 제목은 `WIP: <지금까지 한 것>`, 본문에는 다음 단계와
  반쯤 이해한 것을 적는다. **클라우드 세션은 컨테이너가 사라지므로 반드시 push한다.** PR이 있으면 같은 내용을 설명의
  *헛발질*이나 *NOT VERIFIED*에 더한다.
- 내가 한 커밋 안 된 변경을 남기지 않는다.

## 3. 상태를 기록한다

- 작업 중인 이슈에 댓글 하나: 어디까지 했나, 브랜치/PR, 다음 단계. 상태 칸은 그대로 "지금"(PR이 열렸으면 "검토 중" -
  로컬은 `gh project item-edit`, 클라우드는 `명령:상태-검토중` 라벨).
- 새로 찾은 일·버그·확인 못 한 것은 각각 이슈로 만든다(주인이 정할 일은 담당자 kirnata77, 폰 확인은 `명령:검증-실기기필요`).
- 헛발질을 포함한 경위는 PR 본문이나 이슈 댓글에 둔다. 핸드오프 전용 파일은 만들지 않는다.

## 4. 시작 프롬프트를 준다

요약 두세 줄을 쓰고, 새 세션에 붙여 넣을 코드 블록을 준다:

```text
이 저장소(DFzero)를 session-resume 스킬로 이어서 시작해 줘.
이어서 할 일: 이슈 <#번호> <작업>, 브랜치 <브랜치>, PR <#번호 또는 없음>.
지금까지: <한 줄>.
다음 단계: <한 줄>.
주의: <한 줄, 없으면 "없음">.
```

8줄 이내로 한다. 나머지는 git, PR, 상태 기록에 있다.
