# 세션 재개

목표: 짧은 답 하나로 사용자가 지금 상황과 내가 제안하는 다음 일을 본다.
사용자가 확인하기 전에는 아무것도 편집하지 않는다(`repo-workflow`, 계획 먼저).

## 1. 상태를 읽는다

작업 보드(megasunu 보드 #1)가 할 일의 유일한 기록이다(`CLAUDE.md` "작업 보드").

- **어디서나:** `git fetch origin status && git show origin/status:STATUS.md` - 지금, 검토 중, 주인 결정 대기, 실기기 필요,
  미확인, 다음, 로드맵, 백로그. 하루 3번 갱신되므로 맨 위 시각을 보고, 오래됐으면 `Project snapshot` 워크플로를 돌린다.
- **로컬(`gh` 로그인):** 최신이 필요하면 `gh project item-list 1 --owner megasunu --format json`.
- 이어서 할 이슈가 정해져 있으면 그 이슈 하나(본문과 댓글)만 읽는다.

사용자가 `session-handoff`의 시작 프롬프트를 붙여 넣었다면 거기에 브랜치, PR, 다음 단계가 있다: 믿되, 위 자료와 대조한다.

## 2. 최근 작업을 읽는다

- 열린 PR(특히 `claude/*` 브랜치): 상태와 CI 결과.
- 최근 병합된 PR 3~5개: *NOT VERIFIED*와 *헛발질* 부분.
- `git status`와 현재 브랜치. 시작 프롬프트가 보류한 작업이라고 말하지 않는 한 커밋 안 된 변경은 사용자의 것이다.

## 3. 이 세션이 할 수 있는 일을 안다

이 세션이 클라우드 컨테이너인지 사용자의 PC인지 확인한다. **실기기(폰)에서만 확인되는 항목**(STATUS.md "실기기 필요")과 주인 결정("주인 결정 대기")은
이 세션이 확인할 수 없다: 사용자를 기다리는 것으로 적는다.

## 4. 보고한다 (15줄 안쪽)

- **지금 상황:** 한두 줄.
- **지금:** 보드의 "지금"·"검토 중" 이슈.
- **사용자를 기다리는 것**(결정, 실기기 확인)을 먼저, 그다음 **이 세션이 할 수 있는 것**, 그다음 증명되지 않은 것.
- **제안하는 다음 작업:** 하나만, 필요한 게이트와 이 세션이 그걸 돌릴 수 있는지와 함께. 실기기가 필요한 확인은 제안하지 않는다.

그리고 사용자에게 확인하거나 방향을 바꿔 달라고 묻는다.
